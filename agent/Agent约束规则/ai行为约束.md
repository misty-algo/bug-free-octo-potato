# ai-agent.md — AI 行为约束与自检清单

> 前置：先加载 `core-agent.md`（知道自己是谁、边界在哪）。
> 适用场景：AI 的一切产出（代码、文档、方案、commit message）。

---

## AI 在本项目 MUST：

1. 动手前先读上下文：相关业务编号在 `05` 的定义、相关集合在 `06` 的字段、相关代码文件现状。
2. 一次只改一个点，改完可验证，再进行下一个；改动附可复现的验证方式（怎么跑、期望看到什么）。
3. 遵守主人所在域的边界（`core-agent.md` §4）与全部数据 / 业务红线（`data-agent.md`、`business-agent.md`）。
4. 遇到文档间冲突、口径缺失、需求含糊时——**停下来提问**，而不是自行脑补一个实现。
5. 用中文交流与写注释。

## AI 在本项目 MUST NOT：

1. ❌ 写自己域以外的业务代码或动别人的集合（哪怕"只是顺手"）。
2. ❌ 擅自新增 / 修改集合、字段、索引、状态枚举、口径。
3. ❌ 用浮点数表示金额；先查后写地改余额 / 库存 / 状态；物理删除业务数据。
4. ❌ 修改 `01 / 05 / 06` 等共享业务文档（只读）。
5. ❌ 引入新的第三方依赖而不说明理由并经主人确认；重复实现 `pkg/` 已有能力。
6. ❌ 生成假实现 / 空 TODO / 假数据糊弄验收；mock 必须带 `// ADAPTER:` 标注。
7. ❌ 在日志 / 响应中输出未脱敏的敏感信息。
8. ❌ 大批量一次性重构、跨文件大换血式修改。
9. ❌ 手改生成代码（`api/gen/`）；跳过测试直接说"完成了"。
10. ❌ 对"本期不做"的业务（顺风车、自动驾驶、境外、自营车队）写任何实现。
11. ❌ 自行 `git push`、强推、改写历史、绕过 CI（详见 `git-agent.md`）。

## 完成前自检清单（AI 每次交付前逐条回答）

- [ ] 这次改动只涉及我自己的域和自己的集合吗？
- [ ] 涉及金额的字段全部是分（整数）吗？有没有任何 float？
- [ ] 涉及状态机的改动走乐观锁 + 状态日志了吗？流转关系合法吗？
- [ ] 涉及钱包 / 支付 / 券库存的改动是原子操作吗？幂等键在吗？
- [ ] 敏感信息（手机号/身份证/银行卡）加密存储、脱敏展示了吗？
- [ ] 有没有动数据字典里不存在的字段？有 schema 变更需求的话，是否已停下走人工流程？
- [ ] 新代码是否复用了 `pkg/` 既有能力？是否引入了新依赖？
- [ ] 错误走 `pkg/errors`、响应走 `pkg/httpx`、日志走 `pkg/logger` 吗？
- [ ] 单元测试补了吗？`make test` 过了吗？
- [ ] 改动处写了中文"为什么"注释吗？
